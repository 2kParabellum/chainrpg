# Architecture

Целевая архитектура кода игры и правила взаимодействия частей.

Этот файл — единственный, где описывается устройство кода. В `game_design.md`,
`characters.md` и `chambers.md` реализация по-прежнему не описывается, там только игровой смысл.

## Зачем это нужно

Игра выросла из одного файла-прототипа. Ближайшие задачи проекта — главное меню,
несколько уровней, прокачка, новые монстры, разные оружия, новые механики. Каждая
из них в монолите требовала копирования или правки логики в десятке мест.
Архитектура решает ровно четыре задачи:

1. Добавление уровня — это новый файл данных, а не копия игровой логики.
2. Добавление монстра, союзника или оружия — это одна новая запись в реестре.
3. Игровой цикл, состояние партии, игровой контент и данные уровня разделены.
4. Всё остаётся простым: vanilla JavaScript, без библиотек, сборки и backend.

## Технические соглашения

- **Обычные `<script src>`, без ES-модулей.** Игра должна открываться и двойным кликом
  по файлу (`file://`), где ES-модули блокируются браузером, и через локальный сервер.
- **Порядок тегов `<script>` в `index.html` — это контракт зависимостей.** Файл может
  пользоваться только тем, что подключено выше него.
- **Один корневой объект-неймспейс** вместо россыпи глобальных имён: каждый файл вешает
  своё на общий объект игры. Это не фреймворк, просто один корень.
- Никаких библиотек, бандлеров, TypeScript, npm и backend. Рендер — HTML Canvas,
  только геометрические фигуры.

### Шаблон файла

Каждый файл в `src/` устроен одинаково:

```js
(function (G) {
'use strict';
const { CONFIG, state } = G;          // зависимости — деструктуризацией в самом верху
const { dist } = G.math;
...код модуля...
G.combat = { damageUnit, ... };       // публичный интерфейс — одной строкой в самом низу
})(window.Game = window.Game || {});
```

- Зависимости файла видны с первых строк. Если нужного модуля нет среди подключённых
  выше — это нарушение порядка слоёв, а не повод достать его через `window`.
- Тело файла не сдвигается на уровень вправо, чтобы код читался как обычный файл.
- `'use strict'` включён: обращение к необъявленной переменной падает сразу, а не создаёт глобал.

### Ключи неймспейса

`G.CONFIG`, `G.COLORS` — параметры и палитра. `G.math`, `G.collision` — чистые функции.
`G.weapons`, `G.abilities`, `G.allyTypes`, `G.enemyTypes` — реестры оружий, способностей подиумов и типов. `G.debug` — отладка на телефоне,
`G.screen` — экран (размер вида, режим касаний), `G.input` — ввод, `G.touch` — сенсорное управление, `G.controlsPanel` — панель «Управление». `G.level1` … `G.level6` (номер — порядок появления файла, порядок в прохождении задаёт `LEVELS` в `main.js`), тестовые `G.levelTestRam`, `G.levelTestChain` и `G.levelTestRace`, `G.populate` — данные
уровней и заселение. `G.world` — геометрия.
`G.state` — **только данные** партии: цепочка `state.party` (первое звено — Герой), цель движения
`state.moveInput` (ввод движения: газ, поворот, угол джойстика `aim` и точка курсора `toward`), точка, куда Герой едет мышью, `state.moveTarget` (в мире) и остальные списки. `G.session` — функции над ними (создать юнита, сменить его способность
`setAbility`, сбросить партию, ведущий `leader()` — то есть Герой, цепочка юнитов, текущая комната). `G.chain`, `G.combat`,
`G.roaming`, `G.waves`, `G.pod`, `G.race`, `G.bodies`, `G.update` — игровая логика. `G.shapes`, `G.renderer`, `G.hud` — вывод.

## Слои и структура

Пять слоёв, зависимости идут строго сверху вниз.

```
index.html
src/
  config/     тюнинг и палитра        — ни от кого не зависит
    tuning.js       общие параметры: мир, Герой, шипы, подиумы, цепочка и плётка, реген
    palette.js      цвета

  core/       фундамент               — зависит только от config
    math.js         чистая математика без состояния
    collision.js    круг-прямоугольник, движение со столкновениями, отрезок-прямоугольник; indexRects — раскладка
                    прямоугольников по клеткам (у списка с раскладкой moveAndCollide смотрит только ближние)
    debug.js        ?debug=1: FPS и последняя ошибка JS поверх игры; подключается самым первым, ни от кого не зависит
    screen.js       экран: режим касаний (телефон) или клавиатуры, размер канваса × devicePixelRatio, текущий размер
                    вида CONFIG.VIEW (под окно), вертикальное положение, полноэкранный режим
    input.js        клавиатура и мышь -> намерения игрока: команды (перезапуск, подобрать, бросить, пауза) и опрос осей
                    движения; назначения клавиш (переназначаемые, в localStorage) и ожидание клавиши для назначения;
                    приём того же от touch.js; подписи кнопок команд под способ ввода (keyLabel, withKeys)
    touch.js        касания -> те же намерения: HTML-слой с плавающим джойстиком и кнопками, мультитач,
                    сторона джойстика, расстановка и размер кнопок
                    (editLayout), настройки в localStorage; значки паузы и «заново» в углу (только при касаниях)

  content/    игровой контент         — зависит от config и core
    weapons.js      реестр оружий (меч, кулак, копьё, искра, лук, лечение); подключается раньше abilities.js и allies.js
    abilities.js    реестр способностей подиумов (стрелок, медик): цвет, оружие, знак на теле, значок подиума
    enemies.js      реестр типов врагов (мина — тоже запись, с флагами)
    allies.js       реестр типов союзников: Герой и дружочек — тело, базовое оружие, знак
    upgrades.js     реестр улучшений прохождения: название, чьё, описание, числа и рисунок карточки (art)

  levels/     данные уровней          — зависит от config, core, content
    level1.js       «Обучение»: шесть комнат в линию (kind: 'line', gates — выходы закрыты, пока в комнате есть враги;
                    у первой — exitByButton: выход открывает кнопка),
                    у комнат свой размер и план в пикселях, постоянные подиумы (plan.pads) и дружочки (allies.spots),
                    подсказка комнаты (plan.hint — всплывает плашкой при входе: update.js пишет state.room/roomAt, hud.js рисует),
                    случайные появления только в spawnRooms, победа — clearFinalRoom
    level2.js       «Playground»: поле из сетки зон, планировка зон, порталы, старт, условие победы
    level4.js       «Оборона»: одна прямоугольная комната (kind: 'rect') в пикселях, двор (home), база (base), гнёзда врагов (nests), параметры волн (waves), условие победы — продержаться (survive). Стены «зданий» с дверями собирает в списке колонн маленький помощник building() прямо в файле уровня — это сборка данных, не логика
    level3.js       «Boss Fight»: одна круглая арена, планировка, точки дружочков, частоты случайных подиумов (padSpawn), единственный враг — босс (пул из одного типа), старт Героя, условие победы — уничтожить босса
    level5.js       «Логово»: одна квадратная комната (kind: 'rect') с отростками — стена вокруг зала и срезы углов заданы
                    в плане (plan.walls; лесенку среза и Г-укрытия из колонн собирают помощники chamfer() и shelter()
                    прямо в файле — это сборка данных), гнёзда в отростках (nests) и волны с ускорением (waves.ramp), постоянные подиумы
                    «скорости» (plan.pads с { permanent: true }), единственный враг плана — спрут (kraken), победа —
                    destroyType с showHp (в строке состояния HP босса)
    level6.js       «Hit the Count»: квадратная комната (kind: 'rect'), колонны (четыре одинаковые по кругу — помощник around()
                    в файле), гнёзда посередине сторон и волны (waves), в центре Под (plan.pod: место, радиус, goal, cooldown,
                    heal, gap, keepClear, углы выдачи дружочков drops, dropCount); сами дружочки не появляются
                    (allySpawn с maxActive 0, lifetime — сколько ждут выданные Подом); профессии чаще и до 7 (padSpawn.jobs);
                    победа — podCount; в прохождении — после Boss Fight
    testRam.js      тестовый «Ram Test» (G.levelTestRam): квадратная комната (kind: 'rect'), мишень-манекен (dummy), точки
                    дружочков, постоянный подиум «скорости», без случайных подиумов; победа kind: 'none' (никогда),
                    level.upgrades — улучшения на старте. В прохождение не входит: main.js держит его в TEST_LEVELS и
                    строит для него отдельные кнопки в «Выборе уровня»
    testChain.js    тестовый «Chain Tuning» (G.levelTestChain): квадратная комната, четыре постоянных подиума «скорости»,
                    частые дружочки (allySpawn), врагов нет, победа kind: 'none'; флаг tuner — показывать панель ui/tuner.js.
                    Тоже в TEST_LEVELS
    testRace.js     тестовый «Dead Race» (G.levelTestRace): комната kind: 'rect' с дорогой-кольцом (plan.track: углы осевой
                    линии из прямых, ширина, точки старта и чекпоинтов, карманы, правило шипов, зоны без шипов — дорогу,
                    стены и шипы собирает world.js), колонны и гнёзда — обычные plan.pillars / plan.nests, скользкий пол
                    level.ice, волны только из Бычков, победа kind: 'laps', портал с exit.radius.
                    Тоже в TEST_LEVELS
    populate.js     заселение точек уровня по его правилам: типы врагов (и состав волны — rollWave); дружочки ставятся на точки без выбора типа; комната может задать несколько независимых групп врагов (plan.enemies — список), группа может быть anchored (враги не бродят)

  game/       игровая логика          — зависит от всего вышележащего
    world.js        геометрия мира и запросы к ней (линия комнат или поле из зон), шипы, свободное место под подиум,
                    сетка и поля путей; дорога-кольцо plan.track из прямых (стены, шипы, карманы, ворота — world.track) и
                    скользкий пол уровня (world.ice)
    state.js        состояние партии целиком, её сброс, создание юнитов и врагов
    pads.js         случайные появления: подиумы и нейтральные дружочки около Героя, таймер жизни, исчезновение, padUnder
    pod.js          Под «Hit the Count»: проезд цепочки по нему, счёт дружочков, лечение, перезарядка, выдача дружочков в углах
                    (updatePod), podMates
    race.js         гонка «Dead Race»: ворота старта-финиша и невидимых чекпоинтов (world.track.gates), счёт кругов, время
                    круга, дружочки, пересёкшие линию (updateRace); время текстом и итоги (raceClock, lapTime, raceSummary)
    chain.js        цепочка: след, следование «плёткой», вербовка, бросок, нокаут, выдача способностей подиумами
    combat.js       урон, снаряды, взрывы, эффекты, средовой урон
    roaming.js      общие движения врагов: блуждание по комнате, сход с шипов, погоня за игроком, осада базы
    waves.js        волны из гнёзд («Оборона», «Логово»): таймеры гнёзд, размер и состав отряда, ускорение по ходу партии, выход врагов
    bodies.js       тела: расталкивание врагов между собой и цепочки с врагами по массе
    exit.js         выход с уровня: после победы — волна от базы (если есть база) и светлый портал (level.exit; радиус —
                    exit.radius или общий), Герой в портале — цепочка втягивается следом, затем state.status = 'win'
    update.js       порядок обновления кадра, движение Героя, правила партии

  render/     вывод                   — читает состояние, но не меняет его
    shapes.js       примитивы отрисовки; холст непрозрачный (сцена закрывает его целиком). Штамп свечения glow — готовая
                    картинка мягкого круга (одна на цвет) вместо нового градиента каждый кадр: глаза врагов, пятно под
                    ждущими, подиумы, сферы, порталы, окошко. spriteCache/stamp — готовые картинки частей тел (foes.js,
                    blobs.js): рисуются один раз в разрешении холста, дальше копируются (нерастянутые — пиксель в пиксель).
                    drawOn(c, fn) — на время fn модули, подписанные через onCtx (blobs, foes, padart), и сами примитивы
                    рисуют в чужой холст c (рисунки карточек улучшений)
    blobs.js        блобы своих (Герой, звенья, выбитые, ждущие вербовки): тело, глаза, шапка профессии, оружие по уровню,
                    знаки и эффекты усилений Героя, цепь «крепкости». Анимация выводится из изменений юнита между кадрами
                    (свой кэш на юнита и свои частицы — это не состояние игры). Тело, глаза (зрачки — 16 направлений),
                    шапка, оружие с рукой, вторая рука, «!» выбитого — готовые картинки (колыхание шапок и оружия —
                    кадрами); живьём — тень, вспышка, эффекты усилений, искры шара, капли, плюсики, полоска HP. Значок усиления
                    (glyphAt) и шапка с оружием для подиума (hatIconAt) — тоже готовыми картинками. Стиль — graphics.md
    padart.js       подиум усиления: плита с деталями, появление (пунктир, тень из круга в квадрат, падение, пыль) и исчезновение,
                    постоянный подиум: гаснет, заряжается, загорается. Плита — готовые картинки (зад, перед, узор вставки
                    кадрами); живьём — свечение, мерцание вставки, частицы
    terrain.js      рисунок окружения: тёмная скала вне уровня (бесшовная текстура, рисуется раз на масштаб экрана),
                    пол и подсветка зон, шипы, стены уровня (верх — скала, грань над полом), колонны/двери,
                    пропасть-колодец с мостками, декор на полу (раскладка один раз на уровень), шахматная линия старта
                    «Dead Race» (ворота world.track.gates[0]; чекпоинты не рисуются). paintGround рисует
                    всё неподвижное в заданном куске мира (целиком, нижний или верхний слой); живое — туман и камешки
                    пропасти (drawPitLife). Каждый кадр сам ничего не рисует — это делает ground.js
    ground.js       земля на экране: неподвижное окружение кусками по 384 пикселя холста (свой кэш, привязан к миру; низ
                    куска — непрозрачный холст, копируется без смешивания; куски закрывают весь экран — фон не заливается;
                    куски у края экрана — заранее, по одному раз в несколько кадров); кусок с пропастью — двумя слоями,
                    между ними живой туман; избушка базы — живая, поверх (ближние блоки, заходящие на неё, — ещё раз).
                    Кэш сбрасывается, когда мир перестроен или сменился масштаб; открылась дверь — куски около неё.
                    Окошко в стене за спрятанными: стена кладётся из готовых кусков только вокруг спрятанных
    jobart.js       подиум профессии: постамент с шапкой, появление и исчезновение как у padart; эффект подбора jobGet
                    (шапка летит на голову, ромбики уровня). Постамент и подпись — готовые картинки
    baseart.js      база «Обороны» — избушка; рисуется в слое стен как блок terrain.js (с окошком за ней). Неподвижное —
                    готовые картинки (зад: тень, фасад, рамы окон; перед: ящики, дверь, крыша, конёк, труба, урон по
                    стадии); живьём — свет и лица в окнах (тоже маленькими картинками), флаг, дым, огонь, покраснение
    fireart.js      стена огня Демона: бегущий фронт, языки, выжженная земля, гаснет вразнобой и тлеет (свой список погасших)
    nestart.js      гнездо врагов: нора, зона выхода волны и плашка «×N Ns»; обрезано по полу (минус стены с верхом).
                    У норы один раз готовятся маска пола вокруг неё, заливка зоны и спокойная нора уже по маске
                    (держится для трёх последних нор); пунктир зоны — дугами по полу. Перед волной и при выходе нора
                    рисуется во временном холсте и обрезается маской. Плашка — готовая картинка на каждый текст
    podart.js       Под «Hit the Count»: каменный круг, 15 огоньков (последний — предел), дуга взвода, счёт «N/15», плашка над
                    ним; рисуется живьём каждый кадр (объект один), вызывает renderer под подиумами
                    (трещины, проседание, пыль); исчезнувшие из state.pads досматривают анимацию в своём списке
    foes.js         враги тёмной расы: целиком — Стрелок, Бычок, Колесница, Скорпион, Зомби, Хантер, катапульта, мина,
                    портал (водоворот в арке, урон — выпавшие камни свода); Демону (Пасть: maw, шип-снаряд mawSpikeShot) и Спруту — тела (их draw в реестре получает это как g.foe). Свой кэш на врага
                    (анимация). Обычные враги собираются из готовых картинок частей (тело в 32 кадрах колыхания,
                    лапки в кадрах шага, лицо по стороне взгляда и состоянию; рисуются при первой надобности,
                    в разрешении экрана): сплющивание и рывок — растяжкой, вспышка — белым силуэтом; живьём —
                    тень, дым сигареты, капли и брызги Зомби, щипок и пружина Скорпиона, полоска HP
    renderer.js     отрисовка мира и сущностей; камера сдвигается на целые пиксели холста (куски земли — пиксель в пиксель).
                    Пули, плевки и плюсики лечения — готовые картинки; уколы копейщика — одним рисованием на слой
    cards.js        рисунки карточек улучшений: фон-пол и заготовки рисования для art записи; свои, враги и подиумы —
                    картинки поля через shapes.drawOn, пули, молнии, лечение, огонь — как в бою
    hud.js          интерфейс, шторка ухода в портал, метки у края экрана, плашка цели уровня, надпись о взятом усилении;
                    «Dead Race»: круг N/5 и время круга, список пройденных кругов (время, дружочки), плашка пройденного круга

  ui/         панели меню (HTML)      — зависит только от core
    controls.js     «Управление»: на компьютере — назначения клавиш и мыши, режим мыши; на телефоне — сторона
                    джойстика, расстановка кнопок
    tuner.js        панель ползунков параметров цепочки (CONFIG.LEADER, CONFIG.CHAIN) на уровне с флагом tuner

  main.js     бутстрап, игровой цикл, смысл намерений ввода, список уровней и их выбор, экраны (меню, пауза,
              поражение, карточки — HTML-панели; пройденный тестовый уровень — свой экран без карточек: итоги гонки
              race.raceSummary и «Again»), видимость и подсветка сенсорных кнопок. Кадр перерисовывается,
              пока идёт партия; в меню, на паузе, после поражения — только при смене экрана или размера холста
              (state.status — единственный источник правды: menu | play | pause | dead | win)
```

### Ответственность модулей

- **config/tuning.js** — параметры, не привязанные к конкретным типам сущностей. `CONFIG.WALL_LIFT` — на сколько рисунок
  стен и колонн поднят над основанием: его читает и `render/terrain.js` (рисует), и `game/world.js` (шипы у подножия стены
  ниже дороги кладёт так, чтобы их было видно).
  Важно: размер комнаты и размер вьюпорта — **разные** параметры. `CONFIG.VIEW` — **текущий** размер вида в единицах
  мира, его переписывает `core/screen.js` под окно и на компьютере, и на телефоне: короткая сторона вида —
  `SCREEN.viewMax`, а в тесном окне — сколько влезет при масштабе `SCREEN.minScale` (свой для компьютера и касаний),
  но не меньше `viewMin`; вертикальное положение телефона разрешает `SCREEN.allowPortrait`, предел пикселей канваса —
  `SCREEN.maxPixels`. Поэтому `CONFIG.VIEW` читают в момент использования,
  а не запоминают при загрузке файла. Параметры джойстика — `CONFIG.TOUCH`, мыши — `CONFIG.MOUSE`.
- **config/palette.js** — все цвета игры.
- **core/math.js**, **core/collision.js** — чистые функции. Не знают ни про мир, ни про состояние.
  В `math.js` лежат и мелкие общие помощники: случайный выбор, перемешивание, удаление из списка.
- **core/screen.js** — экран. Способ ввода решает устройство, размер — окно. Режим касаний включается на сенсорном
  устройстве (`pointer: coarse`, или есть касания и нет наведения — `hover: none`), с первого касания или по `?touch=1` (выключается `?touch=0`); тогда у `body` класс
  `touch`. Сцена в любом режиме — всё окно страницы минус вырез (растягивает CSS через `env(safe-area-inset-*)`,
  screen.js только читает размер сцены и по нему считает вид; видимую область
  `visualViewport` не берём — на iPhone она меняется от зума). Размер перепроверяется и без событий браузера
  (iPhone после поворота сообщает его с опозданием); если iPhone приблизил или отдалил страницу, масштаб сбрасывается. Канвас рисуется
  в разрешении экрана: `pixelScale()` — пикселей канваса в единице вида; рисующий код ставит его через
  `shapes.screenTransform()`. При повороте и изменении окна всё пересчитывается (`onChange`). В вертикальном
  положении у `body` класс `portrait` (плашка «Поверни телефон»).
- **core/input.js** — единственное место, где игра слушает клавиатуру и мышь; касания слушает `touch.js` и отдаёт сюда
  те же намерения (`command`, `setStick`). Действия (`ACTIONS`: движение, «ехать к курсору», команды) назначаются на
  коды клавиш (`ev.code`) и кнопок мыши (`'Mouse0'`…), по два на действие; назначения — в localStorage
  (`getBindings` / `setBinding` / `resetBindings`), ESC и 1 / 2 / 3 закреплены. `captureBinding(fn, el)` — следующая
  клавиша (или кнопка мыши над `el`) уходит в `fn`, а не в игру. Мышь слушается на канвасе и не в режиме касаний.
  Превращает события в намерения (подобрать, бросить, рестарт, пауза) и отдаёт опрос осей движения `moveAxes()` —
  газ, поворот, `aim` (угол джойстика), `toward` (курсор в единицах вида, пока зажата кнопка «ехать к курсору»,
  и один раз после короткого щелчка) и `holdOnly` (настройка мыши «ехать, пока держишь», `getMouseHold` /
  `setMouseHold`); главнее клавиши движения, потом мышь, потом джойстик. `main.js` кладёт результат в
  `state.moveInput` каждый кадр. `keyLabel` / `withKeys` — подписи кнопок команд (назначенная клавиша / «ВЗЯТЬ»), в
  том числе подстановка `{recruit}`, `{drop}` в текстах уровней и `{pack}` в описаниях улучшений; `codeLabel` —
  название клавиши. Больше ничего не решает.
- **core/touch.js** — сенсорный интерфейс: HTML-слой `#touch` поверх канваса и под оверлеем меню. Размеры в пикселях
  экрана, не зависят от масштаба игры. Значки паузы и «заново» в углу (`#corner`) — отдельно от слоя; и слой, и
  значки видны только во время партии и только в режиме касаний. Pointer Events с учётом `pointerId` (мультитач),
  потеря касания — отпускание. Места кнопок (центр в пикселях от нижнего угла своей стороны) и их размер — в
  настройках; `editLayout(onDone)` поднимает слой над меню и даёт перетаскивать кнопки. Джойстик отдаёт в `setStick`
  угол (в мёртвой зоне — null). Не знает про игру: что подсвечивать и когда показывать слой, говорит
  `main.js` (`setGlow`, `setVisible`). Как из угла `aim` и точки `toward` получаются газ и поворот, решает движение
  Героя в `game/update.js`: точка курсора переводится в мир и запоминается в `state.moveTarget` (`updateMoveTarget`:
  клавиши и джойстик её снимают, с `holdOnly` — и отпускание), к ней ведёт `pointSteer`, доехал — снята; угол — `aimSteer`.
  Метку точки на земле рисует `renderer.drawMoveTarget`.
- **ui/controls.js** — панель «Управление» (HTML в `index.html`): показывает настройки своего устройства (что видно,
  решает CSS по классу `touch` у `body`: `kbd-only` / `touch-only`) — таблица назначений клавиш и режим мыши (через
  `input`), сторона джойстика и кнопка расстановки (через `touch`). Зависит только от `core/`; `main.js` открывает её
  из главного меню и из паузы (`openControls(from)`, «Назад» и ESC — `closeControls` туда же), зовёт `open()` перед
  показом и `close()` при уходе.
- **ui/tuner.js** — панель «Chain Tuning» (`#tuner` в `index.html`, строки строит сама): ползунки пишут прямо в
  `CONFIG.LEADER` и `CONFIG.CHAIN` (игра читает их каждый кадр). Значения по умолчанию снимаются при загрузке,
  подвинутые хранятся в `localStorage`. `main.js` каждый кадр зовёт `sync(active, visible)`: `active` — у уровня есть
  флаг `tuner` (подставить подвинутые значения), иначе — вернуть значения по умолчанию; `visible` — идёт партия.
  Зависит только от `config/`.
- **content/weapons.js** — реестр оружий. Одна запись = одно оружие: стартовые характеристики и поведение
  за кадр (`update`), при необходимости рисование (`draw`). Оружие получает от игры сервисы параметром `game`
  и не подключает `game/` и `render/`. У каждого носителя своя копия оружия с личной перезарядкой.
- **content/abilities.js** — реестр способностей подиумов (`G.abilities`) и временных усилений (`G.buffs`: скорость, сила, регенерация, крепкость, шипастость, воля — каждое своим набором полей: множители, `regenRate`, флаг `sturdy`, `contactDmg`/`contactInterval`, флаг `revive`; выдаёт `giveBuff`, снимает `updateBuffs` в `game/chain.js`). Подиум усиления берёт только Герой; таймеры живут на Герое, `syncChainBuffs` каждый кадр копирует их звеньям цепочки и очищает у выбитых, так что все проверки по-прежнему смотрят на `u.buffs` своего звена. `canBeDisplaced` в `chain.js` спрашивает `isSturdy(u)`, `damageUnit` в `combat.js` проверяет флаг `revive` перед смертью союзника, контактный урон «шипастости» считает `applySpikyContact` в `game/update.js`.
  Реестр способностей: Одна запись = одна способность; её ключ — это и тип
  подиума на карте. Запись хранит оружие способности (в том же формате, что `base` у союзника), цвет, знак на теле
  и значок подиума. Способность одинакова для Героя и дружочка.
- **content/enemies.js**, **content/allies.js** — реестры типов. Один тип = одна запись,
  в ней лежат характеристики, поведение и отрисовка этого типа. Это главный модуль
  для расширения игры новыми сущностями. Список полей записи — в шапке каждого файла.
  Записи не подключают `game/` и `render/`: всё нужное они получают параметром —
  `game` (сервисы игры, собирает `game/update.js`) и `g` (примитивы рисования из `render/shapes.js`).
  Особенности типа задаются полями записи, а не проверками по имени типа в общем коде.
  Союзник описывается телом (имя, HP, радиус), базовым оружием `base`, знаком на теле
  и флагом `anchor` (Герой: нельзя выбить, смерть — поражение). Режимов нет: союзники не
  уникальны, а роль звена определяет его способность (`u.ability`), выданная подиумом.
  Поле записи `drawReach` — рисовать врага, даже когда его тело далеко за краем экрана (спрут хранит в себе тени тентаклей
  `e.tentacles`, летящие комья слизи `e.globs` и лужи `e.mines`, которые бывают далеко от тела, и рисует их сам). Спрут
  (`kraken`) — пример босса, у которого все атаки живут в его записи: регенерация своя (`noRegen` + `cfg.regen` в `update`),
  тентакля, всасывание (двигает лежачих и ждущих вербовки через `moveAndCollide`, проглоченных досматривает в `e.eating`),
  пук (облака в `state.clouds` со своими `dps`, `grow` и `color` — их понимают `combat.updateClouds` и рендер), плевок слизью (навесной ком — не снаряд
  `state.projectiles`, а запись в `e.globs`; цель — через `game.nearestTarget`, то есть на прямой видимости) и лужи-мины
  (взрыв — только урон, через `game.blast` с видом `'slime'` — сцена рисует брызги слизи).
  Сюда же относится портал: он — обычная запись врага с флагами `noRegen` и `alwaysActive`,
  порождает врагов через `game.spawnEnemy` (темп берёт из таблицы `spawnEvery` по числу живых порталов, предел порождённых на карте — `maxChasing`) и выбирает типы из `game.chaserTypes` — всех записей,
  у которых есть `chaseSpeed` (то есть подвижных). Порождённый враг получает поле `chasing`,
  и поведение записи (шаблон стрелка, бычок, зомби, хантер) вместо блуждания зовёт `game.chaseStep`.
  `chaseStep` умеет гнаться и за любой другой целью (последний параметр; по умолчанию — Герой):
  так хантер бежит к ближайшему союзнику с обходом препятствий.
- **levels/level1.js … level6.js** — данные одного уровня: название и описание для меню,
  геометрия (`kind`: `line` — комнаты в линию, `field` — поле из сетки зон, `arena` — одна круглая
  комната), планировка комнат или зон, правила случайного состава, старт Героя (`spawn: { room, at }`),
  условие победы (`victory.kind`: `clearFinalRoom` — дойти до последней комнаты и перебить всех, `destroyType` —
  разрушить всех врагов заданного типа, в том числе одного босса, `survive` — продержаться, `podCount` — взвести Под, `laps` — проехать
  кругов по дороге-кольцу). Игровой логики здесь нет. Уровень передаётся
  в `resetGame(level)` и лежит в `state.level`; код, которому нужны данные уровня, берёт их оттуда,
  а не подключает файл конкретного уровня. Необязательные поля уровня, которые читает интерфейс:
  `zoneNames` (названия зон в строке состояния), `victory.label` (подпись счётчика цели; с `victory.showHp` при одной
  оставшейся цели — её HP) и `goal` (цель уровня на плашке в начале партии). Уровень может задать веса типов врагов `enemyWeights` (влияют на состав зон и на выбор типа, который порождает портал). Предела длины цепочки нет: `session.chainSpeedMul()` замедляет Героя по длине цепочки (`CONFIG.CHAIN.slowdown`).
- **levels/populate.js** — общий для всех уровней код заселения: разложить типы по точкам
  по правилам уровня и создать сущности. Союзники не уникальны: каждая точка `allies.spots` даёт дружочка, а
  `scatterAllies` — дружочков, разбросанных по случайным местам указанных зон (заселение выдаёт список [тип, зона],
  точку подбирает `state.js`). Враги комнаты задаются либо точками (`spots`), либо
  числом (`count`): во втором случае точки в результате не указаны, и их подбирает `state.js`
  по реальной геометрии. У точек союзников есть необязательный `chance` — вероятность появления.
- **Уровень «Оборона» (`levels/level4.js`, `game/waves.js`)**. Геометрия `kind: 'rect'` — одна прямоугольная комната,
  план в пикселях. План задаёт двор `home` (прямоугольник; пол подсвечен), базу `base` (`at`, `size`, `hp`) и гнёзда
  `nests` (точки). `world.js` кладёт здание базы в `world.solids` — оно держит движение (`moveBlockers`), но не обзор
  и не выстрелы (`sightBlockers`), — а `state.js` создаёт по нему `state.base`: юнит `kind: 'base'` с HP и кругом цели,
  вписанным в здание. `session.enemyTargets()` — по кому бьют враги: цепочка (первым — Герой), лежачие и база; его
  получают `type.update` врагов, вражеские снаряды и облака. `damageUnit` по базе с нулём HP — поражение.
  Гнёзда — не враги: их таймеры лежат в `state.nests` (`nextIn`, номер волны `wave`), `waves.updateWaves` выпускает
  отряд размером `⌊size.first + size.grow · wave⌋` (не больше `maxAlive` живых врагов волн), состав — `populate.rollWave`
  (не больше `kinds` типов, веса уровня). Пауза до следующей волны — `interval`, а с `waves.ramp` она линейно сокращается до
  `ramp.to` за `ramp.time` секунд партии (`intervalNow`). Враг волны получает поля `chasing` (действует на любом расстоянии),
  `fromNest` (по нему считается предел) и `siege` — только если на уровне есть база; без базы («Логово») враг волны —
  обычный охотник и идёт к Герою.
  **Осада** в `roaming.chaseStep`: если цель не задана, враг с `siege` идёт к ближайшему союзнику в радиусе
  `waves.sight` на прямой видимости, иначе к базе (по её полю путей `world.baseFlow`, см. «Поля путей»). Подиумы и дружочки на старте ставятся только во дворе, потом — только вне его (`pads.placeRule` →
  необязательный фильтр `accept` у `world.freeSquareNear`). Победа `victory.kind: 'survive'` — `state.time ≥ time`.
- **Уровень «Hit the Count» (`levels/level6.js`, `game/pod.js`)**. Комната `kind: 'rect'`, гнёзда и волны — как в «Логове»
  (`waves.js`, без базы враги волн идут к Герою). План задаёт `pod`; `world.js` кладёт его в `world.pod` (`x, y, r` и числа
  плана, углы `drops` — уже прямоугольниками мира) — это фикстура пола, ничего не блокирует и в списки препятствий не
  входит. Счёт и таймер — `state.pod` (`count`, `passing`, `touched` — звенья, уже проехавшие за проезд, `lastTouch`,
  `cooldown`, `countAt`, `dropped` — выдача за этот проезд уже была, `drops` — выданные группы `{ side, x, y, mates, at }`;
  сброс партии создаёт его по `world.pod`, на других уровнях `null`). Выдачу `dropMates` (раз за проезд) запускает хвост
  цепочки (`state.party` последний), попавший в `touched`, а если он не доехал — конец проезда: угол — случайный из тех,
  где группы ещё нет, кроме угла, выбранного `maxRepeat` раз подряд (`state.pod.lastSide` / `streak`), дружочки — `pads.spawnMates(угол, dropCount)` (каждый в своём свободном месте угла через
  `freeSquareIn` мимо `occupied()`, `life` — из `allySettings().lifetime`, уходят как обычные), подиум профессии —
  `pads.spawnJobPad(угол)` (тот же `spawnPad` с прямоугольником вместо кольца около Героя: метка-тень, потом подиум);
  `x, y` группы — середина угла (на неё смотрят стрелка и метка у края). Группа, из которой никого не осталось в `state.neutrals`, убирается из
  `state.pod.drops` в начале `updatePod`. `pod.updatePod` (шаг кадра сразу после появлений подиумов и дружочков): пока
  Под отматывается (`cooldown > 0`), только тикает; иначе звено цепочки, чья середина над кругом, начинает или продолжает
  проезд, впервые за проезд — лечится на `heal` своего HP и, если это не Герой, прибавляет `count`; `gap` секунд никого —
  проезд кончился, `cooldown = pod.cooldown`. После победы (`state.cleared`) Под замирает. Победа `victory.kind: 'podCount'`
  в `update.isVictory` — `state.pod.count ≥ world.pod.goal`; портал выхода — `level.exit` на месте Пода. `pads.occupied()`
  держит круг `keepClear` вокруг Пода свободным от новых подиумов и дружочков. Рисует `render/podart.js` (зовёт
  `renderer.drawScene` до подиумов; стрелки к группам — там же), строку состояния, метки «POD» и «×N» к группам у края —
  `hud.js` (`G.pod.podMates()` — дружочков в цепочке без Героя).
- **Уровень «Dead Race» (`levels/testRace.js`, `game/race.js`)**. Комната `kind: 'rect'`, а в плане — дорога-кольцо
  `plan.track` (в пикселях). Ось — замкнутая ломаная из горизонталей и вертикалей; `world.js` (`addTrack`) делает из неё
  отрезки `world.track.segments` (`ax, ay, bx, by`, направление `tx, ty`, длина `len`, полуширина `hw`, повороты на концах
  `turnIn` / `turnOut`: плюс — направо по ходу). Проходимо — прямоугольник вокруг каждого отрезка (шире на `hw` во все
  стороны, углы прямые) и карманы `pockets`; остальное в комнате — стены прямоугольниками через `complementRects` (тот же
  разбор «всё, что не покрыто», что у комнаты-пропасти: сетка по краям, полосы по строкам, склейка одинаковых). Колонны и
  гнёзда — обычные `plan.pillars` / `plan.nests` (ставятся раньше дороги). Шипы по правилу `spikes` (`trackSpikes`)
  раскладываются без случайности (хэш от номера места): у стен — по местам длиной `step` с долей `outer` / `inner` /
  `straight` (внешняя или внутренняя сторона ближнего угла, прямая), подряд занятые места — одна полоса; место берётся,
  только если сразу за ним стена (не проём в соседний отрезок или карман); у стены ниже дороги полоса толще на
  `CONFIG.WALL_LIFT` — столько пола у её подножия закрывает рисунок стены; посреди дороги — квадраты через `middle`, не
  ближе `middleGap` к колоннам. В колоннах, карманах и зонах `clear` шипов нет. Ворота `world.track.gates` — поперёк
  дороги в ближайшей к точке плана точке оси: `[0]` — у `start`, дальше `checkpoints` (`{ x, y, tx, ty, half }`, концы
  уходят в стены). Сброс партии создаёт `state.race` (на других уровнях `null`).
  `race.updateRace` (шаг кадра сразу после Пода): для каждого звена цепочки — отрезок от прошлой позиции
  (`state.race.prev`, Map звено → точка) до нынешней; `crossing` — прошёл ли он ворота и в какую сторону (по знаку
  проекции на направление гонки, точка пересечения — не дальше `half` от середины). Герой: вперёд — только через
  ворота `gates[счёт mod n]`, назад — через `gates[(счёт − 1) mod n]` (счёт −1); на линии при новом наибольшем счёте —
  старт (`startAt`) или круг (`laps.push({ time, mates: 0, at })`). Дружочек, пересёкший линию вперёд после Героя, —
  `mates + 1` последнему кругу, раз (`counted`); после победы Герой ворота не считает, дружочки досчитываются.
  Победа `victory.kind: 'laps'` — `state.race.laps.length ≥ victory.laps`; портал — `level.exit` за линией, с
  `exit.radius`. Скользкий пол — `level.ice` → `world.ice` (`{ brake, drift }`): `update.updateLeader` берёт эти поля
  поверх `CONFIG.LEADER`, а запись Бычка смотрит `game.world.ice` (своё торможение рывка `iceBrake`, рывок за
  `chargeMaxDist` докатывается). Линию старта рисует `terrain.js`, круг, время и список кругов — `hud.js`
  (`race.raceClock`, `race.lapTime`), итоги на экране победы — `main.js` (`race.raceSummary`).
- **Поля путей (`world.js`, `roaming.js`)**. При сборке мира `world.js` покрывает его сеткой клеток `CONFIG.NAV.cell`;
  клетка закрыта у стен, колонн, дверей и пропастей (`world.pathBlockers`, отступ `NAV.clearance`). `buildFlowField(цели)` —
  расстояния от ближайшей цели до каждой клетки (Дейкстра по 8 соседям, диагональ не срезает углы; цели — точки или
  прямоугольники), `flowDir(поле, x, y)` — куда шагнуть, `pathClear(a, b, r)` — свободна ли прямая для тела радиуса r.
  Поле к базе (`world.baseFlow`) строится вместе с миром; поле к союзникам (цепочка и лежачие) пересчитывает
  `roaming.allyFlow` не чаще раза в `NAV.allyEvery` и только если кто-то из них перешёл в другую клетку (иначе поле то же
  самое — `buildFlowField` отдаёт прошлое), хранит в `state.allyFlow` (сброс партии — `null`). `chaseStep`
  идёт по прямой, если `pathClear`, иначе по полю (к базе — по полю базы, к остальным — по полю союзников); у самой цели —
  старый обход вдоль стены. Подход Бычка и Зомби к цели — тоже через `chaseStep`. `freeSpotInRoom` предпочитает
  точки перебежки, до которых путь свободен.
- **Раскладка по клеткам (`core/collision.js` → `indexRects`)**. Списки препятствий `world.sightBlockers`,
  `pathBlockers`, `moveBlockers` (перестраиваются вместе с дверями) и `world.spikes` несут раскладку `index`: видимость,
  свободный путь, шипы, столкновения и клетки сетки путей (при сборке мира) проверяют только прямоугольники в клетках рядом, в том же порядке, что и в списке,
  — результат тот же, что при полном переборе (столкновение, унёсшее тело за запас, пересчитывается по всему списку).
  `nearestTarget` сначала считает только расстояния и проверяет стены от ближней цели к дальней до первой видимой.
  Расталкивание (`bodies.js`) раскладывает врагов по клеткам 128 px и проверяет только пары в соседних клетках.
- **Тела (`game/bodies.js`)**. `separateBodies` — один проход расталкивания за кадр, после ходов врагов: пары враг–враг
  (кроме связанных полем `linked` — колесница и её катапульта) и звено цепочки–враг. Перекрытие делится обратно массам (`cfg.mass`, нет поля — 1, `Infinity` — неподвижен), сдвиг —
  через `moveAndCollide`, в стены не заталкивает; о неподвижное тело звено теряет скорость в его сторону. Враг с флагом
  `passThrough` (его ставит Бычок на время рывка) сквозь цепочку проходит. Звенья между собой, лежачие и нейтралы не толкаются.
- **Выход с уровня (`game/exit.js`)**. `update.js` при первом выполнении условия победы зовёт `exit.onVictory`
  (`state.cleared`, новые волны не выходят). Без базы сразу открывается портал `state.exit` в точке `level.exit`
  ({ room, at } в координатах плана комнаты); с базой — сперва `state.shockwave`: кольцо растёт на `EXIT.waveSpeed`,
  сносит врагов, вражеские снаряды, облака и гнёзда (`state.nests`), дойдя до дальнего угла — открывает портал.
  Герой коснулся портала — `state.leaving`: Герой стоит в центре портала и не управляется (`updateLeader` не зовётся),
  звенья вместо обычного шага идут `followChain(a, dt, i, pull)` — точка на следе подтягивается к Герою на `pull`,
  дошедшее звено получает `absorbed` (не рисуется); союзники в это время неуязвимы (`damageUnit`). Через
  `EXIT.irisTime + EXIT.hold` — `status = 'win'`. Шторку-круг рисует `hud.drawIris`, экран «уровень пройден» /
  «вы прошли игру» и переход к следующему уровню списка `LEVELS` — HTML-панель в `main.js` (пробел — дальше).
- **Улучшения (`content/upgrades.js`)**. Взятые лежат в `state.upgrades` (ключи) — единственное поле состояния, которое
  сброс партии не трогает: так улучшения переходят на следующий уровень. `session.startRun()` очищает их (уровень из меню),
  `session.upgrade(key)` — запись, если взято, иначе `null`; оружию тот же вызов отдаётся как `game.upgrade`. Числа
  улучшения лежат в его записи и читаются там, где оно действует: стрела (`weapons.arrow`: веер, поджог — поле снаряда
  `burn`, горение врага `e.burn` тикает в `combat.updateBurns`), искра (молнии — список `w.beams`), лечение (`heal`),
  урон (`combat.damageUnit(u, dmg, hit)`: ближние атаки врагов передают `hit = { by, melee: true }`; прикрытие
  `coverDefense` снижает любой урон соседям копейщика), копьё (`weapons.spear`: сторона удара, «Double Edge», «Berserk»),
  пробивающие стрелы (поле снаряда `passChance`, задетые — `p.hit`, флаг типа врага `boss` — в `combat.updateProjectiles`),
  долгое лечение (поле звена `u.cure`, тикает `applyCure` в `update.updateWeapons`), «Lucky Foot» (`pads.settings`),
  рюкзак (`state.backpack`, команда `pack` → `chain.usePack`, перехват подиума в `chain.touchPads`; ячейка — `hud.drawBackpack`), тяжесть цепочки (`chainMass` — масса для разгона, торможения и сцепления на повороте в `update.updateLeader`, `chainSpeedMul` — потолок скорости), таран Героя (`update.applyHeroRam` сразу после
  движения Героя: масса `ramMass` × скорость, `ramDamage`; силу для дуги кладёт в `lead.ramPower`, дугу рисует `renderer.drawChain`;
  в `damageUnit` передаёт `hit = { ram, mass, speed }`). Тип врага может задать `onDamage(e, dmg, hit, game)` — `damageUnit`
  зовёт его после каждого урона до проверки гибели (мишень-манекен: цифры урона — эффект `dmgText`). Ранг: запись с `tier: 2` предлагается (`main.offerable`), только если у того же `who` уже взято улучшение 1-го ранга. Карточки показывает `main.js` на экране «уровень пройден» и перед стартом не с первого уровня (`prepareLevel`: N−1
  выборов, что дальше — в `afterPick`): три случайных невзятых, без выбора дальше не пускает; рисунок — `render/cards.drawCard`, который зовёт `art(ctx, k)` записи с заготовками рисования.
- **game/state.js** — единственный объект, в котором лежит вся партия: цепочка (`party`, первое звено —
  Герой), цель движения, нейтралы, лежачие, враги, снаряды, эффекты, облака, таймеры пушек-ловушек
  (`cannons`, по одному на `world.cannons`), след, камера, исход.
  Здесь же сброс партии, создание юнитов (`makeAlly` копирует в юнит тело и базовое оружие плоским списком
  `u.gear`), смена способности (`setAbility`: пересобирает `u.gear` новыми личными копиями оружия, `null` —
  снова базовое), создание врага посреди партии.
  Уровень может задать `startParty` — сколько дружочков уже стоят в хвосте цепочки при старте партии,
  без вербовки (сейчас ни один уровень этим не пользуется).
- **game/world.js** — вся статическая геометрия: сборка мира из уровня, пересчёт координат
  комнаты, номер комнаты по точке, прямая видимость, запросы про шипы и свободные точки
  (`scatterSpot` — для стартовой расстановки, не на шипах; `freeSpotNear` — куда встаёт порождённый
  враг; `freeSquareNear` — свободный квадрат под подиум). Подиумы — не часть мира: см. `game/pads.js`.
  «Комната» для остального кода — это комната линейного уровня, зона поля или единственная комната
  круглой арены: номер и внутренний прямоугольник (у арены — квадрат, описанный вокруг круга; план
  комнаты сам следит, чтобы точки попадали внутрь круга). Круглая стена арены — не отдельный примитив
  столкновений, а обычные прямоугольники: заливка полосами по строкам всего, что снаружи круга,
  так что коллизии по-прежнему считает `core/collision.js` без изменений. **Всё знание о раскладке — что
  комнаты стоят в линию, что мир — сетка зон со стенками на стыках, или что комната одна и круглая —
  живёт только здесь.**
  В линии комнат у каждой комнаты может быть свой размер (`plan.size`), центры по высоте совпадают — там лежат
  проходы. План комнаты может быть в пикселях её внутреннего прямоугольника (`plan.units: 'px'`) вместо долей;
  пересчёт знает только этот модуль (`localToWorld`, `planScale`). Комната-пропасть (`plan.chasm`) перечисляет
  только проходимое — мостки (ломаные с шириной) и островки; `addChasm` сам собирает пропасть из прямоугольников-
  дополнения (сетка по краям, склейка в полосы), помечая их `seamless` (рисуются без швов), а мостки кладёт
  в `world.bridges` только для рисования.
  План может задать сплошные стены `plan.walls` (как колонны, но цветом и смыслом стены — так «Логово» обносит квадратный
  зал с отростками внутри прямоугольной комнаты).
  Здесь же живут двери и кнопки (`world.doors`, `world.buttons`, `buttonUnder`), неуязвимые пушки-ловушки
  (`world.cannons`) и финишная зона (`world.finish`) — фикстуры удалённого уровня «Тропа над пропастью», сейчас не используются, задаются в плане
  комнаты так же, как колонны. Двери-выходы «Обучения» (`geometry.gates`) — те же двери с полем `room` (чей выход): `clearOpens` — открывает
  зачистка комнаты, у комнаты с `plan.exitByButton` вместо этого `latch` — дверь открывает кнопка плана и, открывшись, не
  закрывается. От кнопки к её закрытым дверям рисуется бегущий пунктир. Закрытая дверь блокирует движение и обзор, как колонна; `setDoorsOpen` переключает
  состояние дверей и пересобирает `world.moveBlockers`/`sightBlockers` — единственное место в игре, где мир
  меняется по ходу партии, а не только при сбросе (см. инварианты ниже). Сама пушка не хранит своего
  таймера — он в `state.cannons`, по одному на каждую запись `world.cannons`.
- **Обучение (`levels/level1.js`)**. Выходы-двери: `geometry.gates` — `world.js` кладёт в проём правой стены каждой
  комнаты линии, кроме последней, дверь с полем `room`; `update.updateDoors` открывает её навсегда, как только врагов с
  `e.room` этой комнаты не осталось (мины не в счёт). Постоянные подиумы: `plan.pads` — `state.js` при сбросе кладёт их в
  `state.pads` с флагом `fixed` и огромным временем жизни; `pads.respawnFixed` после взятия или исчезновения ставит на то
  же место метку, через `PAD_SPAWN.fixedRespawn` — снова подиум. `level.spawnRooms` — случайные подиумы и дружочки
  появляются (и их таймеры идут) только пока Герой в этих комнатах, и только внутри его комнаты (`pads.placeRule`).
  Подсказку комнаты (`plan.hint`) и метку «ДАЛЬШЕ» к открытому выходу рисует `hud.js`. Враг с флагом `rangedOnly`
  (дверь-мишень) неуязвим для ближнего боя: оружие спрашивает `game.meleeHittable(e)`.
- **game/pads.js** — случайные появления: подиумы и нейтральные дружочки (`updateAllySpawns`, параметры `CONFIG.ALLY_SPAWN`,
  уровень может переопределить через `level.allySpawn`; у ждущего дружочка `life`/`maxLife`). Общий таймер — `runSpawner`.
  Подиумы: Они часть состояния партии (`state.pads`: прямоугольник, ключ способности или
  усиления, остаток и полное время жизни), а не мира. `updatePads` уменьшает таймеры, убирает истёкшие; у профессий и усилений
  свои таймеры (`state.jobSpawnIn`, `state.buffSpawnIn`) и параметры (`CONFIG.PAD_SPAWN.jobs` / `.buffs`, уровень может
  переопределить через `level.padSpawn`). Новый подиум сперва — метка-тень в `state.padMarks` (через `telegraph` секунд
  становится подиумом), место — свободное около Героя (`world.freeSquareNear`). После сброса партии таймеры `null` —
  первый вызов сразу выкладывает стартовые подиумы. `padUnder(u)` отвечает, какого подиума
  касается тело юнита; `markPadUsed(pad)` (зовёт `chain.touchPads` при каждом касании) запускает/продлевает таймер
  исчезновения `pad.usedLeft` — подиум одноразовый; `pad.takenBy` — кто уже взял с него (каждое звено берёт один раз).
  Постоянный подиум усиления (`pad.permanent`, из `plan.pads` с `{ permanent: true, cooldown }`, «Логово»): берётся как
  обычный (`markPadUsed`), но когда `usedLeft` кончился, `updatePads` не убирает его, а гасит на `pad.cooldownTime` секунд
  (`pad.cooldown`; погасший `padUnder` не видит, рисует его `renderer.drawPadCooldown` с таймером); в пределы `padCount` не входит, рамку вокруг него (`CONFIG.PADS.permanentFrame`)
  рисует `renderer.drawPermanentFrame`, `occupied()` держит место с учётом рамки. `occupied()` у громадин берёт радиус
  `cfg.keepClear`, если он задан (спрут: подиумы и дружочки не появляются в зоне всасывания). С `anywhere: true` в
  `level.padSpawn` / `level.allySpawn` место бросается не в кольце около Героя, а в любой точке его комнаты
  (`world.freeSquareIn`).
  Подиум профессии: `chain.jobTarget` выбирает получателя (первый от головы дружочек без профессии, иначе звено той же
  профессии с низшим уровнем — прокачка `setAbility(u, key, level + 1)`; Герой профессий не берёт), `consumePad` убирает подиум; переопределения уровней —
  `levels` в записи способности. Производные характеристики звена (множители усилений, HP от уровня) пересчитывает
  одна функция `session.recalcStats(u)`; усилений у звена сколько угодно, порядок взятия — `u.buffOrder`.
  Выбитые союзники (`state.downed`) действуют оружием, как звенья (`updateWeapons` в `update.js`), и враги получают
  в своём `update` список целей «цепочка + лежачие» (первым — Герой). Рисование (появление, мигание и песочные часы перед исчезновением) — в `render/renderer.js`.
- **game/chain.js** — цепочка как механика: след Героя, следование звеньев «плёткой» (`followChain`: пружина с
  затуханием к точке следа, параметры `CHAIN.whip`), вербовка, бросок, выбивание и протяжка лежачего (только
  дружочков: Героя вытеснить нельзя), выдача способностей подиумами (`touchPads`). `knockOutAlly` — единая точка
  выхода из цепочки (таран, гарпун, X); способность звена при этом сохраняется. `displaceAlly` — толчок атаки: звено
  цепочки выбивает (если можно), лежачего отбрасывает по полу; им пользуются таран Бычка и Демона и большой снаряд.
  `hookAlly` тянет к Скорпиону и лежачих. `cutChain(i)` — цепочку перерубили перед звеном i (тентакля спрута): оно и все
  за ним выпадают из цепи без отброса (кого можно выбить); отдаётся типам врагов как `game.cutChain`.
- **game/combat.js** — всё, что наносит урон: снаряды (в том числе навесные — катапульта и большой снаряд босса,
  выбивающий задетых союзников из цепочки), взрывы по площади, лучевой мгновенный удар и стенки огня после него
  (атаки босса), эффекты, шипы, облака, смерть сущности. Здесь же `updateCannons` — неуязвимые пушки-ловушки
  мира: не сущность и не враг, просто по таймеру пускают ядро строго по прямой. Ядро — обычный снаряд с полями
  `kind: 'cannon'`, `pierce` и `hit`: сквозной снаряд не гаснет о цель, а ранит каждого из цепочки и лежачих
  один раз; рисуется отдельным слоем (`renderer.drawCannonShots`, вызывается из `main.js` после сцены).
- **game/update.js** — порядок кадра явным списком, движение Героя («танковое»: направление `heading` отдельно от взгляда оружия `facing`;
  `aim` от джойстика переводится в те же газ и поворот — `aimSteer`) и правила партии: каждое звено работает
  оружием из своего `u.gear`; активация врагов (по расстоянию до Героя; порталы и охотники активны всегда),
  победа по правилу уровня (`destroyType`, `clearFinalRoom` или `reachPoint` — Герой дошёл до `world.finish`),
  поражение (смерть Героя), камера по обеим осям (цель камеры — `session.cameraTarget()`: мир уже вида — посередине). `updateDoors` — тоже здесь: проверяет, лежит ли на кнопке
  брошенный союзник, и переключает связанные двери через `world.setDoorsOpen`.
  Бросок X (`chain.dropLastAlly`) кладёт дружочка на кнопку, если Герой стоит на ней.
- **render/** — только вывод. Читает состояние, никогда его не меняет.
- **main.js** — игровой цикл, смысл намерений ввода (что значит «подобрать», «бросить»),
  список уровней (`LEVELS`), «Играть» (новое прохождение с первого уровня) и «Выбор уровня» в главном меню, пауза
  (ESC, кнопки паузы, `visibilitychange`, вертикальное положение), экраны (панель «Управление» — `ui/controls.js`).
  Оверлей главного меню в HTML только отражает `state.status`; кнопки выбора уровня строятся
  из списка `LEVELS`.

## Правила зависимостей

1. Зависимости идут только вниз по списку слоёв. `core` не знает про `game`,
   `content` не знает про `levels`, `game` не знает про `render`.
2. **`render` не меняет состояние.** Любая мутация из рисующего кода — ошибка.
3. **`game/world.js` — единственный владелец знания о раскладке мира.** Если нужна
   геометрия, спрашиваем у него, а не пересчитываем формулой на месте.
4. **Состояние партии живёт только в `game/state.js`.** Модули получают его аргументом
   или читают у него, но не заводят собственных копий игровых списков. Сброс партии
   подменяет массивы целиком, поэтому обращаться к ним нужно всегда как `state.party`
   в момент использования — списки нельзя сохранять в локальные переменные модуля
   и нельзя деструктурировать из `state` при загрузке файла. Мир (`world`) по ходу партии не меняется
   и пересобирается только при сбросе партии — **кроме дверей**: кнопка переключает их открыто/закрыто
   на лету и пересобирает `moveBlockers`/`sightBlockers`, это единственное намеренное исключение.
5. **Тип сущности не знает про другие типы.** Если поведению нужны чужие параметры
   (например, лежачего тащит скорпион), эти параметры записываются в саму сущность
   в момент события, а не читаются из чужого конфига.
6. **Характеристики копируются в сущность при создании**, а не берутся ссылкой на реестр.
   Иначе любая прокачка изменит характеристики сразу у всех сущностей этого типа. Это касается и оружия:
   у каждого юнита свои копии оружия, с личными перезарядками; смена способности пересобирает их заново.
7. **Способность принадлежит звену и сохраняется при выбивании из цепи**; меняет её только подиум (`setAbility`). Оружие звена — только `u.gear`: «режимов» у звена нет. Всё, что зависит от того, кто
   впереди (камера, цель охотников, активация), спрашивает `leader()` — это всегда Герой.
8. `levels` содержит данные, а не логику. Логика, общая для уровней, живёт в `populate.js`.

## Как расширять игру

- **Новый монстр или союзник** — одна запись в реестре `content/`: характеристики,
  поведение, отрисовка. Существующий код не трогается. Если тип нужен в случайном
  составе комнат, он добавляется в пул нужного уровня.
- **Новый уровень** — новый файл в `levels/` с планировкой и правилами, тег `<script>` в `index.html`
  и строка в списке `LEVELS` в `main.js` (кнопка в меню появится сама). Игровая логика
  не копируется. Если уровню нужна геометрия другой формы, меняется только `game/world.js`;
  если нужен новый вид условия победы — правило в `game/update.js` и, при необходимости, строка
  состояния в `render/hud.js`.
- **Новое оружие** — одна запись в `content/weapons.js` (характеристики, `update`, при необходимости
  `draw`); его подключают к базовому оружию союзника (`allies.js`) или к способности (`abilities.js`). Общим
  шаблонам (ближний удар, выстрел) уже есть функции в шапке файла.
- **Новая способность** — запись в `content/abilities.js` (оружие, цвет в палитре, знак, значок) и её ключ с весом
  в `CONFIG.PAD_SPAWN.jobs.weights` (подиумы с ней начнут появляться случайно). Остальной код не меняется.
- **Новый тип союзника** — запись в `allies.js` (тело, базовое оружие, знак) и цвет в палитре; чтобы он встречался
  на уровне, `populate.js` учит ставить его на точки.
- **Прокачка** — опирается на правило 6: характеристики у каждой сущности свои,
  поэтому их можно менять поштучно.

## Инварианты, которые нельзя ломать

- **Порядок обновления кадра фиксирован**: Герой (движение), след, затем звенья цепочки (Герой первым),
  **подиумы** (выдача способностей, затем таймеры и появление новых подиумов и дружочков), **Под**, **гонка** (ворота и круги), лежачие, двери, **волны** (выход новых врагов),
  враги, **расталкивание тел**, снаряды, горение, облака, шипы, мины, эффекты, проверка победы и **выход** (волна базы,
  портал). Таран Героя (улучшение) — сразу после движения Героя. Перестановка меняет баланс.
- Список врагов, доступных дальнему оружию (`state.targetableEnemies`: все, кроме необнаруженных мин), считается
  один раз за кадр **до** обновления звеньев.
- Сущность, меняющая роль (нейтрал -> звено цепочки -> лежачий -> звено), сначала убирается
  из старого списка, потом меняет роль, потом добавляется в новый.
- Героя из `state.party` не убирают даже после смерти: партия заканчивается, а сцена и камера
  не остаются без ведущего.
- Списки сущностей перебираются по копии, если внутри цикла кто-то может умереть.
- Порядок создания сущностей при старте партии влияет на случайный расклад.
  Менять его без причины нельзя. В пределах комнаты: союзники, порталы, враги, мины
  (порталы идут раньше врагов, чтобы те расставлялись мимо них); разбросанные союзники
  ставятся после всех комнат. Состав союзников бросается до расстановки комнат, одним броском на уровень.
- Мина — особый враг: не блуждает, не действует сама, не попадает в счётчик врагов,
  не мешает победе, видна и атакуема только после обнаружения. Эти свойства задаются
  флагами в её записи в реестре, а не условиями по всему коду.

## Чем реальный код пока отличается от схемы выше

Три этапа переноса завершены, целевая структура достигнута; второй уровень (поле, порталы, выбор уровня
в меню) уложился в неё без новых слоёв. Остаётся один известный пробел.

| Что | Сейчас | Цель |
|---|---|---|
| Снаряды и эффекты особых видов | Гарпун, навесной снаряд катапульты, облако и их отрисовка живут в `game/combat.js` и `render/renderer.js`; облако читает параметры Зомби из реестра | Новый вид снаряда не требует правок общего кода |

Также пока нет системы прокачки.

## Чего в архитектуре сознательно нет

ECS, dependency injection, event bus, scene-граф, машины состояний как фреймворка,
сборки, тестового фреймворка, пулинга объектов, общего поиска пути по запросу (A* для каждого врага).
Простая раскладка по клеткам (`indexRects`, клетки тел в `bodies.js`) есть: в драке с 40–90 врагами на слабом телефоне
перебор всех стен и всех пар занимал больше половины логики кадра. Вместо A* — поля путей на сетке
(`world.buildFlowField`): одно поле обслуживает всех врагов, идущих к одной группе целей (к союзникам или к базе).
Без них враги подолгу тупили у бортов пропастей и упирались в длинные стены двора «Обороны». Проект маленький, всё перечисленное стоит дороже, чем
решает. Если что-то из этого понадобится — сначала доказательство необходимости,
потом правка этого файла.
