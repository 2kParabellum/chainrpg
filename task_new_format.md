# Задача: новый формат игры (4 изменения)

Ты работаешь в репозитории браузерной игры CHAIN (vanilla JS, Canvas, без сборки). Перед началом прочитай
`agent.md` (правила работы, их соблюдай), `architecture.md` (слои и правила зависимостей), `game_design.md`.
Это служебный файл с заданием: он не входит в документацию проекта, в коммиты его не добавляй.

Делай изменения **по порядку, четырьмя отдельными коммитами** (один пункт — один коммит), чтобы любой
пункт можно было откатить отдельно. После каждого пункта проверь игру (см. «Проверка») и только потом коммить.

## Принятые решения (пользователь может их поменять)

- **S** — задний ход на пониженной скорости (пользователь назвал WASD, но описал только «вперёд и повороты»).
- Случайными становятся **все** подиумы: и способности (стрелок, медик), и усиления (скорость, сила,
  регенерация, крепкость, шипастость, воля). Статичных подиумов на уровнях больше нет.
- Подиум **не расходуется** при взятии (как сейчас): пока лежит, его могут взять несколько звеньев.
  Исчезает только по таймеру.
- Подиумы появляются **в кольце вокруг Героя** (примерно в пределах экрана), а не в любой точке карты:
  поле Playground — 4×4 экрана, и подиум в дальнем углу без карты и указателей бесполезен.
- Движковые механики, которыми пользовались только удаляемые уровни (линия комнат, мины, двери, кнопки,
  пушки, пропасти-мостки, финиш, `solidEnemies`, `startParty`), **в коде остаются**. Удаляем только
  данные уровней и всё, что связано с подиумами (их всё равно переделываем).

## 3. Управление клавишами вместо мыши («танковое»)

- **W** — вперёд по направлению Героя, **S** — назад (скорость × `reverseMul`),
  **A / D** — поворот налево / направо. Работает и в зажатом состоянии, и в сочетаниях (W+A — едет по дуге).
  Мышью Герой больше не управляется. ПРОБЕЛ, X, R — как раньше.
- Клавиши определяй по `ev.code` (`KeyW`, `KeyA`, `KeyS`, `KeyD`), а не по `ev.key` — у пользователя
  русская раскладка. По желанию продублируй стрелками (тогда `preventDefault`, чтобы страница не скроллилась).

**Ввод** (`core/input.js`): убрать обработчики мыши (кроме запрета контекстного меню). Хранить множество
зажатых клавиш движения; на `window` `blur` очищать его (иначе после Alt+Tab Герой едет сам). Отдать
наружу опрос `moveAxes()` → `{ throttle, turn }`: `throttle` = +1 (W), −1 (S), 0 (ничего или обе);
`turn` = −1 (A), +1 (D), 0. Обнови шапку файла.

**main.js**: убрать `mouseDown`, `toWorld`, `onPointer*`. В цикле перед `update(dt)` писать
`state.moveInput = G.input.moveAxes()`. Кнопка «МЕНЮ» больше не трогает `mouseDown`.

**state.js**: `moveTarget` заменить на `moveInput: { throttle: 0, turn: 0 }`; у Героя новое поле
`heading` — направление движения (радианы). При старте: `level.spawn.heading`, по умолчанию `-Math.PI / 2`
(вверх; на арене босс как раз сверху).

**Важно: `heading` ≠ `facing`.** Оружие (`meleeUpdate`, `shootUpdate`, `heal`) при атаке поворачивает
`u.facing` к цели. Если двигать Героя по `facing`, меч будет разворачивать его к врагу. Поэтому движение —
только по `heading`, `facing` оружию не мешаем.

**update.js, `updateLeader`** — новая модель (инерция и скольжение по стенам сохраняются):

```
mv = lead.moveMul || 1                         // усиление «скорость» ускоряет и ход, и поворот
lead.heading += turn * turnSpeed * mv * dt      // A уменьшает угол (в экранных координатах y вниз это поворот налево)
want = (heading-вектор) * speed * mv * (throttle > 0 ? 1 : throttle < 0 ? -reverseMul : 0)
скорость (vx, vy) тянется к want: на accel*mv*dt за кадр, если throttle ≠ 0, иначе на brake*mv*dt
дальше как сейчас: moveAndCollide + slideAlongWall, pushOutOfEnemies для solidEnemies
lead.facing = lead.heading
```

Поворот налево-направо **не должен** быть перепутан: проверь, что A при взгляде вверх ведёт влево по экрану.

**tuning.js, `LEADER`**: убрать `arriveRadius`, добавить `turnSpeed: 3.4` (рад/с, ~полоборота за секунду)
и `reverseMul: 0.55`. `speed`, `accel`, `brake`, `wallFriction` не менять.

**Отрисовка**: удалить `drawTargetMarker`. Направление Героя должно читаться сразу: «нос» Героя
(`hero.mark` в `content/allies.js`) рисуй по `u.heading` (если есть), а не по `facing`; плюс добавь перед
Героем маленькую стрелку-шеврон на расстоянии ~r+8 по `heading` (в `renderer.drawChain`, только для
ведущего).

**Тексты**: строка подсказок в `index.html` (`#bar`) и таблица «Управление» в меню — W/S/A/D вместо ЛКМ.
Документы: `game_design.md` («Core gameplay» п.1, «Инерция движения», «Управление»), `architecture.md`
(`core/input.js`, `state.moveTarget` → `moveInput`).

Готово, когда: Герой едет и поворачивает клавишами, цепочка идёт за ним плёткой как раньше, удар мечом не
разворачивает Героя, после Alt+Tab Герой не едет сам, клик мышью ничего не делает.

## 4. Подиумы появляются случайно и исчезают

Сейчас подиумы — статичная часть мира (`world.pads`, собираются из `plan.pads` / `plan.padChoice`).
Теперь это **динамические объекты партии**: появляются в случайное время в случайном месте около Героя,
случайного типа, живут случайное время и исчезают; за `warnTime` секунд до исчезновения над подиумом
появляется значок-предупреждение.

**Данные и место в архитектуре** (правило: мир по ходу партии не меняется, всё изменяемое — в `state`):

- `state.pads = []` (сбрасывается в `resetGame`), элемент: `{ x, y, w, h, ability, life, maxLife }`
  (прямоугольник как раньше, `ability` — ключ из `G.abilities` или `G.buffs`). Плюс `state.padSpawnIn` —
  секунды до следующего появления.
- Новый модуль **`src/game/pads.js`** (`G.pads`), подключается в `index.html` после `game/state.js` и до
  `game/chain.js`. В нём: `padUnder(u)` (переезжает из `world.js`, читает `state.pads`),
  `spawnPad()`, `updatePads(dt)`. `state.js` подключён раньше `pads.js` и звать его не может, поэтому
  `resetGame` только обнуляет: `state.pads = []`, `state.padSpawnIn = null`. Стартовые подиумы кладёт
  первый же вызов `updatePads`: видит `padSpawnIn === null` → создаёт `startCount` штук и заводит таймер.
- `chain.touchPads` и `renderer` (`drawPads`, `drawPadLinks`) берут `padUnder` из `G.pads` и список из
  `state.pads`.
- Из `world.js` удалить: `world.pads`, сборку подиумов в `addRoomContent`, `padUnder`, `overlapsPad`
  (и его проверку в `scatterSpot` — на старте подиумов больше нет). Из `populate.js` удалить `rollPadChoice`.
- Из планов `level2.js` и `level3.js` удалить все `pads: [...]`, поправить комментарии в шапках планов.
- В `world.js` добавить запрос свободного места под подиум, например
  `freeSquareNear(x, y, minR, maxR, size, avoid)`: ~30 попыток случайной точки в кольце; квадрат `size`
  целиком в пределах мира, не пересекает `moveBlockers` (стены, колонны, пропасти), не лежит на шипах и не
  ближе чем на 20 px к кругам из `avoid` (`[{ x, y, r }]`); `null`, если не нашлось.

**Параметры** — в `config/tuning.js`, новая группа (числа — стартовые, их будут крутить):

```
PAD_SPAWN: {
  startCount: 2,          // сколько подиумов сразу при старте партии
  maxActive: 4,           // больше одновременно не бывает
  interval: [5, 12],      // пауза между появлениями, сек (случайно в диапазоне)
  lifetime: [15, 25],     // сколько живёт подиум, сек
  warnTime: 4,            // за сколько секунд до исчезновения показать значок
  ringMin: 180,           // появляется в кольце вокруг Героя: не ближе ..
  ringMax: 650,           // .. и не дальше
  weights: { shooter: 3, medic: 2, speed: 1, power: 1, regen: 1, sturdy: 1, spiky: 1, will: 1 },
}
```

Уровень может переопределить поля: действующие параметры = `{ ...CONFIG.PAD_SPAWN, ...level.padSpawn }`.
В `level3.js` (арена) задай `padSpawn: { weights: { ...как выше, но power: 3 } }` — «сила» единственная
пробивает щит босса выстрелами, на арене она должна попадаться чаще.

**Логика `updatePads(dt)`**:

- `life -= dt` у каждого; `life <= 0` — удалить (эффект `ring` цветом подиума при исчезновении).
- `padSpawnIn -= dt`; при `<= 0` и если подиумов меньше `maxActive` — `spawnPad()`; следующий через
  случайное из `interval`. Если места не нашлось — повторить через 1 с.
- `spawnPad()`: тип — `pickWeighted` из `G.math` по `weights`, по возможности не тот, что уже лежит на
  карте; место — `freeSquareNear` вокруг Героя, `avoid` = остальные подиумы + порталы и босс (их круги);
  `life = maxLife` = случайное из `lifetime`; при появлении эффект `ring`.
- Подиум при взятии не исчезает (см. «Принятые решения»).
- Порядок кадра в `update.js`: `touchPads(); updateBuffs(dt); updatePads(dt);` — взятие раньше
  исчезновения. Обнови список порядка кадра в инвариантах `architecture.md`.
- В меню / после победы / поражения ничего не тикает (это уже обеспечивает `update`).

**Отрисовка** (`render/renderer.js`, состояние только читает):

- Подиум рисуется как сейчас (`drawPads`, теперь по `state.pads`, яркость 1).
- Появление: первые ~0.3 с подиум «вырастает» (масштаб/прозрачность от 0).
- Предупреждение, когда `life <= warnTime`: над правым верхним углом подиума значок — песочные часы
  цветом `COLORS.warning` (два треугольника вершинами друг к другу), и сам подиум мигает, всё чаще к концу
  (например, период мигания от 0.5 с до 0.15 с). Последние ~0.3 с — быстро гаснет.

**Документы**: `game_design.md` («Подиумы и способности» — как теперь появляются, живут, предупреждают;
«Игровые параметры»), `characters.md` («Где кого брать», подиумы усилений), `chambers.md` (убрать подиумы
из описаний зон и арены), `architecture.md` (новый модуль `game/pads.js`, подиумы — часть `state`, а не
`world`; убрать `rollPadChoice`, `padChoice`, `plan.pads`).

Готово, когда: на старте 2 подиума рядом, дальше они появляются и пропадают сами, одновременно не больше 4,
не появляются в стенах, колоннах, пропасти, на шипах, на портале и боссе; за 4 с до исчезновения видны
часы и мигание; ПРОБЕЛ на подиуме выдаёт способность/усиление как раньше.
